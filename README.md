# awesome-coding-agent-evals

A curated list of benchmarks, harnesses, datasets and papers for evaluating and training coding agents, where every entry was fetched from its own page and carries its year and licence.

## How entries are chosen and checked

- Every entry was fetched on the date recorded in `data/entries.json` (2026-11-06): the GitHub repository through the GitHub API, the paper through its arXiv abstract page, or the dataset through its Hugging Face card. An entry whose page could not be fetched is left out. Nothing is listed from memory.
- **Year** is the year of the paper's first arXiv version, or of the repository's or dataset's first release as shown on its page.
- **Licence** is what the repository, dataset card or arXiv page states. For code and data it is the licence of that artifact; `not stated` means the page gives none, which does not mean the artifact is free to reuse. For papers it is the licence of the paper text on arXiv, followed by the venue when the arXiv page names one.
- **Kind** is `code`, `dataset`, `code+data` (a repository that ships both) or `paper`.
- Each summary is one plain sentence written for this list from the fetched page. There are no star counts, rankings or claims about which tool is best.

## Quickstart

The list is plain Markdown; the scripts are only needed to change it. They use the Python standard library, and the tests use pytest through [uv](https://docs.astral.sh/uv/).

```console
$ git clone https://github.com/vipul21435/awesome-coding-agent-evals
$ cd awesome-coding-agent-evals
$ uv run python scripts/validate.py
ok: 67 entries in 7 sections
$ uv run python scripts/render.py --check
README.md is in sync with the data file
$ uv run pytest -q
18 passed in 0.02s
```

Status: 67 entries in 7 sections, each fetched on 2026-11-06. Not implemented yet: a script that re-fetches every page and reports changed licences or moved URLs, any link check (CI is offline on purpose), and several areas that are not yet covered, such as security and web-agent benchmarks.

## Tools by the author of this list

These are the author's own projects, not independent entries, and they were not chosen by the rules above. They cover parts of the evaluation workflow that the papers in this list discuss.

- [commitminer](https://github.com/vipul21435/commitminer): mines candidate fail-to-pass tasks from repository history and ranks them.
- [reporewind](https://github.com/vipul21435/reporewind): resolves Python fix commits and pull requests into exact source and test patches.
- [taskledger](https://github.com/vipul21435/taskledger): schema validation, lint rules and content hashing for benchmark task bundles.
- [graderguard](https://github.com/vipul21435/graderguard): audits task graders for holes that let wrong solutions pass, and for flaky results.
- [evalstats](https://github.com/vipul21435/evalstats): error bars, paired comparisons, pass@k and sample-size planning for evaluations.
- [trajlens](https://github.com/vipul21435/trajlens): reads coding-agent trajectories, measures run behaviour and classifies failures by stated rules.
- [testlogs](https://github.com/vipul21435/testlogs): parses pytest, JUnit XML and TAP output into per-test records and diffs two runs.
- [judgebias](https://github.com/vipul21435/judgebias): checks a model judge for position, length and self-preference bias and agreement with humans.
- [patchmin](https://github.com/vipul21435/patchmin): delta debugging over the hunks and lines of a fix to find the part that makes the target tests pass.
- [issuelint](https://github.com/vipul21435/issuelint): checks issue-to-fix task records for solution leaks, test leaks and underspecification.
- [sftlint](https://github.com/vipul21435/sftlint): lints chat, SFT and tool-calling datasets for structure, tool-call validity, secrets and duplicates.
- contamscan: not yet public on GitHub as of 2026-11-06.

## Contributing

1. Fetch the page of the thing you want to add and read it.
2. Add one record to `data/entries.json` with `name`, `url`, `section`, `kind`, `year`, `licence`, `summary` (one sentence, in your own words) and `fetched` (the date you fetched it); `venue` is optional for papers.
3. Run `uv run python scripts/render.py` to regenerate the tables, then `uv run python scripts/validate.py` and `uv run pytest`.

The validator works offline: it checks required fields, URL shape, year range, duplicate URLs and names, known sections, and that the README tables match the data file. It does not check that links are still live.
