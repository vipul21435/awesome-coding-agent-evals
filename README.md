# awesome-coding-agent-evals

A curated list of benchmarks, harnesses, datasets and papers for evaluating and training coding agents, where every entry was fetched from its own page and carries its year and licence.

## How entries are chosen and checked

- Every entry was fetched on the date recorded in `data/entries.json` (2026-11-06): the GitHub repository through the GitHub API, the paper through its arXiv abstract page, or the dataset through its Hugging Face card. An entry whose page could not be fetched is left out. Nothing is listed from memory.
- **Year** is the year of the paper's first arXiv version, or of the repository's or dataset's first release as shown on its page.
- **Licence** is what the repository, dataset card or arXiv page states. For code and data it is the licence of that artifact; `not stated` means the page gives none, which does not mean the artifact is free to reuse. For papers it is the licence of the paper text on arXiv, followed by the venue when the arXiv page names one.
- **Kind** is `code`, `dataset`, `code+data` (a repository that ships both) or `paper`.
- Each summary is one plain sentence written for this list from the fetched page. There are no star counts, rankings or claims about which tool is best.

## Function-level code benchmarks

Self-contained problems scored by running unit tests on a single generated function or program.

| Name | Year | Kind | Licence | What it is |
|---|---|---|---|---|
| [APPS](https://github.com/hendrycks/apps) | 2021 | code+data | MIT | 10,000 coding problems collected from competitive programming sites, ranging from introductory to competition level, graded by test cases. |
| [HumanEval](https://github.com/openai/human-eval) | 2021 | code+data | MIT | 164 hand-written Python problems, each a function signature and docstring checked by unit tests, with the harness that runs them. |
| [MBPP](https://huggingface.co/datasets/google-research-datasets/mbpp) | 2021 | dataset | CC BY 4.0 | About 1,000 crowd-sourced entry-level Python problems, each with a task description, a reference solution and three test cases. |
| [DS-1000](https://github.com/xlang-ai/DS-1000) | 2022 | code+data | CC-BY-SA-4.0 | 1,000 data science problems drawn from StackOverflow and spanning seven Python libraries such as NumPy and Pandas, with execution-based checks. |
| [EvalPlus (HumanEval+ and MBPP+)](https://github.com/evalplus/evalplus) | 2023 | code+data | Apache-2.0 | Framework that adds many generated test inputs to HumanEval and MBPP so that plausible but wrong solutions are caught. |
| [BigCodeBench](https://github.com/bigcode-project/bigcodebench) | 2024 | code+data | Apache-2.0 | Python tasks that require calls to many functions across common libraries, offered as docstring completion and as natural-language instructions. |
| [CRUXEval](https://github.com/facebookresearch/cruxeval) | 2024 | code+data | MIT | 800 short Python functions, each with one input-output pair, used for two tasks: predict the output from the input and predict an input for the output. |
| [LiveCodeBench](https://github.com/LiveCodeBench/LiveCodeBench) | 2024 | code+data | MIT | Code benchmark that keeps adding problems from programming contests with their release dates, covering generation, self-repair, test output prediction and execution. |

8 entries, all fetched on 2026-11-06.

## Contributing

1. Fetch the page of the thing you want to add and read it.
2. Add one record to `data/entries.json` with `name`, `url`, `section`, `kind`, `year`, `licence`, `summary` (one sentence, in your own words) and `fetched` (the date you fetched it); `venue` is optional for papers.
3. Run `uv run python scripts/render.py` to regenerate the tables, then `uv run python scripts/validate.py` and `uv run pytest`.

The validator works offline: it checks required fields, URL shape, year range, duplicate URLs and names, known sections, and that the README tables match the data file. It does not check that links are still live.
